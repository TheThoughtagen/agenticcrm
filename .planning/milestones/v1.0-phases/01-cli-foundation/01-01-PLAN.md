<task type="auto" tdd="true">
  <name>Task 1: Create frontmatter editor, validation module, and format module</name>
  <files>src/frontmatter.rs, src/validation.rs, src/format.rs, Cargo.toml</files>
  <behavior>
    - update_field("status: active", "status", "archived") returns "status: archived" with surrounding text unchanged
    - update_field preserves YAML comments (lines starting with #) untouched
    - update_field preserves blank lines and field order
    - update_field for non-existent field appends it before the end
    - update_array_field("tags:\n  - \"rust\"\n  - \"cli\"", "tags", vec!["new"]) replaces the entire array block
    - parse_raw_frontmatter extracts the raw YAML string between --- delimiters
    - validate_contact returns error when name is empty
    - validate_contact returns error when id is empty
    - validate_contact returns Ok for a valid contact
    - validate_contact checks follow_up_cadence is a known value if non-empty
    - OutputFormat::Human prints Display output, OutputFormat::Json prints serde_json output
  </behavior>
  <action>
    1. Add dependencies to Cargo.toml: `serde_json = "1"`, `regex = "1"` (dialoguer added in plan 02).

    2. Create `src/frontmatter.rs` with:
       - `pub fn parse_raw_frontmatter(content: &str) -> Result<(String, String)>` — returns (raw_yaml_between_delimiters, body). The raw YAML includes comments, blank lines, everything between the `---` delimiters verbatim.
       - `pub fn update_field(raw_frontmatter: &str, key: &str, new_value: &str) -> String` — uses regex `(?m)^(key:\s*)(.*)$` to find and replace a scalar field value in-place. If field not found, appends `key: value` before the last line.
       - `pub fn update_array_field(raw_frontmatter: &str, key: &str, values: &[String]) -> String` — replaces an array field. Detects the field start line (`key:`) and all subsequent indented lines (starting with spaces/`  -`), replaces with new values in block style (`\n  - "val1"\n  - "val2"`). If values is empty, writes `key: []`.

    3. Create `src/validation.rs` with:
       - `pub struct ValidationError { pub field: String, pub message: String }`
       - `impl Display for ValidationError` — formats as `{field}: {message}`
       - `pub fn validate_contact(contact: &Contact) -> Vec<ValidationError>` — checks:
         - `id` is non-empty
         - `name` is non-empty
         - `follow_up_cadence` if non-empty must be one of: "weekly", "biweekly", "monthly", "quarterly", "yearly"
         - `status` if Some must be a valid Status variant (already enforced by serde, but validate here for raw edits)
       - Return empty vec for valid contacts.

    4. Create `src/format.rs` with:
       - `#[derive(clap::ValueEnum, Clone, Debug, Default)] pub enum OutputFormat { #[default] Human, Json }`
       - `pub fn output<T: Serialize + std::fmt::Display>(data: &T, format: &OutputFormat) -> Result<()>` — matches on format, prints Display for Human, serde_json::to_string_pretty for Json.

    5. Write tests in each module (tests submodule) covering the behaviors listed above. For frontmatter.rs, use the actual contact template format with `# Contact`, `# Professional` comments to verify preservation.
  </action>

  </verify>
