   - `AddParams { name: String }` -- "Full name of the new contact, e.g. 'Jane Smith'"
   - `EditParams { name: String, sets: Vec<String> }` -- name: "Contact name or partial match", sets: "Field-value pairs, e.g. ['company=Acme', 'role=Engineer']"
   - `LogParams { name: String, interaction_type: String, summary: String, notes: Option<String> }` -- interaction_type: "One of: coffee, call, email, message, conference, meeting, lunch, intro"
   - `DeleteParams { name: String }` -- "Contact name to delete permanently"
   - `ArchiveParams { name: String }` -- "Contact name to archive"
   - `SyncParams { direction: String, force: bool (default false), dry_run: bool (default false) }` -- direction: "Sync direction: 'pull', 'push', or 'both'"

2. Add write `#[tool]` methods to the CrmServer tool_router impl:

   a) `add_contact(params: AddParams)`:
      - Acquire `self.write_lock.lock().await` BEFORE spawn_blocking
      - Clone root, spawn_blocking `ops::contact::add(&root, &params.name)`
      - Serialize AddResult to JSON, return success

   b) `edit_contact(params: EditParams)`:
      - Acquire write_lock, spawn_blocking `ops::contact::edit(&root, &params.name, &params.sets)`
      - Serialize EditResult to JSON

   c) `log_interaction(params: LogParams)`:
      - Acquire write_lock, spawn_blocking `ops::contact::log_interaction(&root, &params.name, &params.interaction_type, &params.summary, params.notes.as_deref())`
      - Serialize LogResult to JSON

   d) `delete_contact(params: DeleteParams)`:
      - Acquire write_lock, spawn_blocking `ops::contact::confirm_delete(&root, &params.name)`
      - Use confirm_delete directly (MCP is non-interactive; the agent decides to call delete)
      - Serialize DeleteResult to JSON

   e) `archive_contact(params: ArchiveParams)`:
      - Acquire write_lock, spawn_blocking `ops::contact::archive(&root, &params.name)`
      - Serialize ArchiveResult to JSON

   f) `sync_contacts(params: SyncParams)`:
      - First check `self.allow_sync` -- if false, return `CallToolResult` with `is_error: true` and message "Sync is disabled. Start the server with --allow-sync to enable sync operations."
      - If allowed: load SyncCredentials from keyring (same pattern as CLI sync command -- read from `keyring::Entry` for "acrm-server", "acrm-username", "acrm-password", or from sync config). Look at how `src/commands/sync.rs` loads credentials and replicate that approach.
      - Acquire write_lock
      - Match on `params.direction`: "pull" -> sync_pull, "push" -> sync_push, "both" -> sync_bidirectional
      - Build SyncOpts from params.force, params.dry_run, filter: None
      - Serialize result to JSON

   CRITICAL for all write tools: Acquire write_lock BEFORE spawn_blocking. The lock guards the critical section. Pattern:
   ```rust
   let _guard = self.write_lock.lock().await;
   let result = tokio::task::spawn_blocking(move || { ... }).await??;
   // _guard drops here, releasing lock
   ```
