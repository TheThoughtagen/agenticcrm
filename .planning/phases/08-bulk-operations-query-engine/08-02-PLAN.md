Bulk {
    /// Query predicate (e.g. 'status=dormant', 'tags~friend')

**3. Create `src/commands/bulk.rs`:**

`run_bulk()` function:
1. Parse query string with `Query::parse(&query)`
2. Call `ops::contact::query(root, &q)` to get matched contacts
3. If no action flags (no --set, --delete, --archive, --add-tag, --remove-tag): just display matched contacts as a list (name, company, status). Support JSON output via `fmt`. Return early.
4. If action flags present:
   a. Show preview: list affected contact names (truncate at 20 with "...and N more")
   b. Show what action will be performed and count
   c. If `--dry-run`: show "[DRY RUN]" prefix, set dry_run=true for ops call
   d. If not `--yes` and not dry_run: prompt with `dialoguer::Confirm` "Apply to N contacts?"
   e. Call appropriate ops function based on flags:
      - `--set` present: `ops::contact::bulk_update()`
      - `--delete`: `ops::contact::bulk_delete()`
      - `--archive`: `ops::contact::bulk_archive()`
      - `--add-tag`/`--remove-tag`: `ops::contact::bulk_tag()`
      - Can combine --set with --add-tag/--remove-tag (run both)
   f. Display BulkResult summary

`run_bulk_update()` function:
1. If `--stdin` flag: read JSON from stdin with `std::io::stdin().read_to_string()`
2. Check `std::io::stdin().is_terminal()` -- if TTY and --stdin, print error "No input piped. Usage: acrm search ... --format json | acrm bulk-update --stdin --set ..."
3. Deserialize JSON as `Vec<StdinContact>` where StdinContact has `name: String` and optional `path: Option<String>`
4. For each StdinContact, resolve to ContactFile:
   - If `path` is Some, load directly via `store::parse_contact_file`
   - If only `name`, use `store::load_all_contacts` + fuzzy match (load once, match all)
5. Apply same action logic as run_bulk (preview, confirm, execute)
6. Share common logic between run_bulk and run_bulk_update via helper functions

**Display format for human output:**
- Query-only (no action): table of name | company | status (like `acrm list`)
- Preview: numbered list of contact names with planned action
- Result: "Updated N contacts" / "Deleted N contacts" / etc.
- Dry run: "[DRY RUN] Would update/delete/archive N contacts" with change list

**Display format for JSON output:**
- Query-only: serialize matched contacts as SearchMatch array (same format as `acrm search --format json`)
- Result: serialize BulkResult directly

**Error handling:**
- Empty query string: "Query is required"
- No matches: "No contacts match query 'X'" (not an error, just informational)
- Stdin not piped: helpful error message
- Invalid stdin JSON: "Invalid JSON from stdin: {parse_error}"
