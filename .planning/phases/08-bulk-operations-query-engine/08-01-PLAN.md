  <name>Task 1: Create query engine with predicate parser and Contact matcher</name>
  <files>src/query.rs, src/main.rs</files>
  <behavior>
    - parse("status=dormant") produces Query with one Predicate{field:"status", op:Eq, value:"dormant"}
    - parse("status!=active") produces Predicate with op:NotEq
    - parse("tags~friend") produces Predicate with op:Contains
    - parse("status=dormant tags~friend") produces Query with two predicates (implicit AND)
    - parse("status=dormant,tags~friend") also works (comma separator)
    - parse("") returns error (empty query)
    - parse("invalid") returns error (no operator found)
    - matches() on status=dormant returns true for contact with Status::Dormant
    - matches() on status=lost-touch returns true for contact with Status::LostTouch (kebab-case serde)
    - matches() on tags=friend returns true if "friend" is IN the tags list (contains semantics for arrays)
    - matches() on tags~fri returns true if any tag contains "fri" substring
    - matches() on company=Acme returns true case-insensitively
    - matches() with two predicates returns true only if BOTH match
    - get_field_value returns correct values for all Contact fields including enum fields as serde-serialized strings
  </behavior>
  <action>
Create `src/query.rs` with:

1. `Op` enum: `Eq`, `NotEq`, `Contains`
2. `Predicate` struct: `field: String`, `op: Op`, `value: String`
3. `Query` struct: `predicates: Vec<Predicate>`
4. `Query::parse(input: &str) -> Result<Self, OpsError>`:
   - Split input on whitespace and commas to get tokens
   - For each token, detect operator by scanning for `!=`, `~`, `=` (in that order to avoid `!=` matching as `=`)
   - Return OpsError::ValidationFailed for empty input or tokens without operators
5. `Query::matches(&self, contact: &Contact) -> bool`:
   - For each predicate, call `get_field_value(contact, &pred.field)`
   - Apply operator logic: Eq = exact case-insensitive match, NotEq = not equal, Contains = substring
   - For FieldValue::List (array fields): Eq means "any element equals", Contains means "any element contains substring"
   - All predicates must match (implicit AND)
6. `FieldValue` enum: `Single(String)`, `List(Vec<String>)`, `None`
7. `get_field_value(contact: &Contact, field: &str) -> FieldValue`:
   - Map all Contact struct fields by name
   - For Status enum: serialize via serde_json::to_string to get kebab-case (e.g., "lost-touch"), then strip quotes
   - For Relationship/Priority enums: serialize via serde_json to get snake_case
   - For Option<NaiveDate>: format as YYYY-MM-DD string or return None
   - Unknown fields return FieldValue::None (which won't match anything)

Add `mod query;` to `src/main.rs` module declarations. Make query module pub so ops can use it.

IMPORTANT: Status uses `#[serde(rename_all = "kebab-case")]` so serde_json::to_string gives `"dormant"`, `"lost-touch"`, etc. Do NOT use Debug format which gives PascalCase.

Add to `src/ops/contact.rs`:

1. Result structs:
```rust
#[derive(Debug, Serialize)]
pub struct BulkResult {
    pub matched: usize,
    pub affected: usize,
    pub changes: Vec<BulkChange>,
    pub dry_run: bool,
}

#[derive(Debug, Serialize)]
pub struct BulkChange {
    pub name: String,
    pub path: String,
    pub action: String,
}
```

2. `pub fn query(root: &Path, q: &crate::query::Query) -> Result<Vec<ContactFile>, OpsError>`:
   - Call `store::load_all_contacts(root)`, filter with `q.matches()`, return matched set
   - Sort results by name for deterministic output

3. `pub fn bulk_update(root: &Path, matched: &[ContactFile], sets: &[String], dry_run: bool) -> Result<BulkResult, OpsError>`:
   - For each matched contact, re-load its file individually (to get fresh raw_frontmatter)
   - Apply the same key=value edit logic from `edit()` (extract the parsing into a helper or inline)
   - Use `frontmatter::update_field`/`update_array_field`, re-parse, validate, write
   - If dry_run, skip the write step
   - Record each change in BulkChange with action like "set status=active"

4. `pub fn bulk_delete(root: &Path, matched: &[ContactFile], dry_run: bool) -> Result<BulkResult, OpsError>`:
   - For each matched contact, remove file with `std::fs::remove_file`
   - If dry_run, skip removal
   - Record "deleted" action

5. `pub fn bulk_archive(root: &Path, matched: &[ContactFile], dry_run: bool) -> Result<BulkResult, OpsError>`:
   - Create archive/ dir, for each matched contact: update status to archived, write to archive/, remove original
   - If dry_run, skip filesystem changes
   - Record "archived" action

6. `pub fn bulk_tag(root: &Path, matched: &[ContactFile], add_tags: &[String], remove_tags: &[String], dry_run: bool) -> Result<BulkResult, OpsError>`:
   - For each matched contact, re-load file, get current tags from raw_frontmatter
   - Add new tags (deduplicate), remove specified tags
   - Use `frontmatter::update_array_field` to write updated tags
   - If dry_run, skip write
   - Record "added tag X" / "removed tag Y" actions

IMPORTANT anti-pattern from research: Do NOT call `edit()` per contact inside bulk_update -- that calls load_all_contacts each time. Instead, the matched contacts are already loaded. Re-load individual files via `store::parse_contact_file(&cf.path)` for fresh raw_frontmatter, apply changes, write.

Add `pub use crate::query;` or ensure query module is accessible from ops. The `query` function in ops/contact.rs imports `crate::query::Query`.
