**Dedup matcher** `fn find_match<'a>(contacts: &'a [ContactFile], name: &str, email: &str) -> Result<Option<&'a ContactFile>, ImportSkip>`:
- `name_lower = name.to_lowercase()`
- `email_lower = email.to_lowercase()`
- Collect name_matches: contacts where `contact.name.to_lowercase() == name_lower` (EXACT, not contains)
- Collect email_matches (only if email non-empty): contacts where any element in `contact.email` matches email_lower (case-insensitive)
- Combine unique matches. If >1 unique contact matched, return Err(ImportSkip) with reason "ambiguous match"
- If exactly 1 match, return Ok(Some(match))
- If 0 matches, return Ok(None)

IMPORTANT: Do NOT reuse `ops::contact::find_contact()` -- it uses `.contains()` (fuzzy). Import needs exact name match per locked decision.

**Main function** `pub fn import_linkedin(root: &Path, csv_path: &Path, dry_run: bool) -> Result<ImportResult, OpsError>`:
1. Call `read_linkedin_csv(csv_path)` to get rows + warnings
2. Call `store::load_all_contacts(root)` to get existing contacts
3. For each LinkedInRow:
   a. Build full name: `format!("{} {}", row.first_name.trim(), row.last_name.trim()).trim()`
   b. Skip if name is empty (add warning)
   c. Call `find_match(&existing, &name, &row.email_address)`
   d. If Err(skip) -> add to skipped list, continue
   e. If Ok(None) -> CREATE new contact:
      - Use `ops::contact::add(root, &name)` to create the contact file
      - Then re-load with `store::parse_contact_file` for fresh raw_frontmatter
      - Apply fields via `frontmatter::update_field`: company, role (position), source="linkedin"
      - Apply email via `frontmatter::update_array_field` if non-empty
      - Apply met_date via `parse_connected_on` + `update_field` if parseable
      - Apply tags: `frontmatter::update_array_field` with ["linkedin"]
      - Apply relationship: `frontmatter::update_field` with "colleague"
      - Serialize and write (unless dry_run)
      - Add to created list with fields that were set
   f. If Ok(Some(existing_cf)) -> UPDATE existing contact:
      - Re-load with `store::parse_contact_file` for fresh raw_frontmatter
      - For each scalar field (company, role, source), check if CRM value is empty:
        - If empty and LinkedIn has value: apply via update_field, record in fields list
        - If non-empty and LinkedIn has different value: record as DetectedChange, do NOT apply
      - For met_date: same fill-empty-only logic with parse_connected_on
      - For email array: get current emails, add LinkedIn email if not already present (case-insensitive dedup), use update_array_field with merged list
      - For tags: get current tags, add "linkedin" if not present, use update_array_field
      - Serialize and write (unless dry_run)
      - Add to updated list if any fields were actually changed (skip if nothing to update)
4. Return ImportResult with all collected data

**Key implementation detail for fill-empty-only:** Check the Contact struct's field value directly (e.g., `existing.contact.company.is_empty()`) rather than regex on raw_frontmatter. Use `update_field` and `update_array_field` on the raw_frontmatter string for actual updates, then `store::serialize_contact_file` + `std::fs::write` to persist.

Write tests in a `#[cfg(test)] mod tests` block at the bottom of the file using `tempfile::TempDir` (same pattern as ops/contact.rs tests). Create test fixtures by writing contact files directly, then running import_linkedin against them.
