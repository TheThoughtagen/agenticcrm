  <name>Task 1: Create push orchestration module</name>
  <files>src/sync/push.rs, src/sync/mod.rs</files>
  <behavior>
    - compute_push_changeset: Contact with no source (not "icloud") -> creates list
    - compute_push_changeset: Contact with source "icloud" + source_id but vCard differs from cache -> updates list
    - compute_push_changeset: Contact with source "icloud" + source_id and vCard matches cache -> skipped (unchanged)
    - compute_push_changeset: Contact with source "icloud" + source_id but server ETag differs from stored ETag -> conflicts list
    - compute_push_changeset: Archived contact with source "icloud" + source_id -> deletes list
    - compute_push_changeset: Contact with source "icloud" but no source_id -> skipped
    - PushResult tracks counts: created, updated, deleted, conflicted, failed
  </behavior>
  <action>
    Create `src/sync/push.rs` with:

    1. **Data structures:**
       ```rust
       pub struct PushChangeset {
           pub creates: Vec<ContactFile>,
           pub updates: Vec<(ContactFile, String)>,  // (contact, cached_vcard)
           pub deletes: Vec<(String, String, String)>, // (source_id, etag, name) for reporting
           pub conflicts: Vec<(ContactFile, String, String)>, // (contact, local_etag, server_etag)
       }

       pub struct PushResult {
           pub created: usize,
           pub updated: usize,
           pub deleted: usize,
           pub conflicted: usize,
           pub failed: usize,
           pub details: Vec<PushDetail>,
       }

       pub struct PushDetail {
           pub name: String,
           pub action: String, // "created", "updated", "deleted", "conflict", "failed"
           pub error: Option<String>,
       }
       ```

    2. **`compute_push_changeset`** function:
       - Takes `crm_root`, `contacts: &[ContactFile]`, `server_entries: &[VCardEntry]` (from fetch_vcard_list)
       - Build HashMap of server_entries: source_id -> etag (extract UID from href using existing extract_uid_from_href logic)
       - For each contact:
         - If `source != "icloud"` or source is empty: it's a new contact -> add to creates
         - If `source == "icloud"` and has source_id:
           - Check server ETag vs stored etag. If different -> add to conflicts
           - Read cached vCard. Serialize current contact via merge_contact_to_vcard (or contact_to_vcard if no cache). Compare with cached text. If different -> add to updates. If same -> skip (unchanged).
       - Load archived contacts from archive/ dir (if exists). For each with source=="icloud" + source_id -> add to deletes.

    3. **`execute_push`** function:
       - Takes `client: &CardDavClient`, `addressbook_url: &Url`, `crm_root: &Path`, `changeset: &PushChangeset`, `force: bool`
       - For creates: serialize via contact_to_vcard, generate UUID for URL, PUT with etag=None, on success update contact frontmatter (source, source_id, etag) and write cache
       - For updates: serialize via merge_contact_to_vcard with cached text, PUT with If-Match etag, on success update etag in frontmatter and update cache
       - For deletes: DELETE with If-Match etag, on success remove cache file
       - For conflicts: if force, treat as updates (re-serialize and PUT). If not force, skip and report.
       - On 412 from PUT/DELETE: report as conflict, do not fail entire push
       - Return PushResult with counts and details
       - After each successful PUT, update the contact's frontmatter etag field with the new ETag from the response

    Update `src/sync/mod.rs` to add `pub mod push;`

    - Contact frontmatter updated with new ETags after push
    - Force flag bypasses conflict check
