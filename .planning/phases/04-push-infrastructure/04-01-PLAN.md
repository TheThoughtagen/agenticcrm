    - merge_contact_to_vcard: Round-trip preserves VERSION and UID from cached vCard
    - merge_contact_to_vcard: Falls back to contact_to_vcard if cached vCard fails to parse
    - read_cached_vcard: Returns None for non-existent file
    - write_cached_vcard: Creates .sync/vcards/ directory if needed, writes file
    - delete_cached_vcard: Removes cached file, no error if missing
    - CRLF: Output uses \r\n line endings (vCard 3.0 requirement)
  </behavior>
  <action>
    Create `src/sync/vcard_write.rs` with two main serialization functions and cache management:

    1. `contact_to_vcard(contact: &Contact) -> Result<String>` -- builds fresh vCard 3.0 from Contact. Uses calcard VCardEntry builder: VERSION:3.0, FN, N (split name into Given;Family), EMAIL (one per entry), TEL (one per entry), ORG, TITLE, URL, BDAY, NOTE, UID (use source_id if set, else contact.id). Only include properties with non-empty values. Serialize with VCard::to_string() and ensure CRLF line endings.

    2. `merge_contact_to_vcard(contact: &Contact, cached_vcard_text: &str) -> Result<String>` -- parse cached vCard, retain entries NOT in CRM_MAPPED_PROPERTIES list (preserving X-properties, PHOTO, TYPE params, etc.), then add current CRM data as new entries via the same logic as contact_to_vcard (but skip VERSION and UID since they're already in the retained entries). This is the parse-overlay-serialize pattern from research.

    3. Cache functions:
       - `cache_dir(crm_root: &Path) -> PathBuf` -- returns crm_root/.sync/vcards
       - `read_cached_vcard(crm_root: &Path, source_id: &str) -> Option<String>` -- reads {source_id}.vcf
       - `write_cached_vcard(crm_root: &Path, source_id: &str, vcard_text: &str) -> Result<()>` -- writes file
       - `delete_cached_vcard(crm_root: &Path, source_id: &str) -> Result<()>` -- removes file

    4. Define CRM_MAPPED_PROPERTIES constant: [Fn, N, Email, Tel, Org, Title, Url, Bday, Note] -- these get removed during merge.

    5. Helper `ensure_crlf(text: &str) -> String` -- replaces bare \n with \r\n (careful not to double-convert existing \r\n).

    Update `src/sync/mod.rs` to add `pub mod vcard_write;`

    Update `.gitignore` to add `.sync/` entry.

    Per research: use calcard's VCardEntry::new(prop).with_value(val) builder pattern. Use VCardValue::Text for most fields, VCardValue::Component for N (Family;Given;;;). Check if vcard.entries is pub -- if not, construct a new VCard from filtered+added entries.
