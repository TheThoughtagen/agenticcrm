<task type="auto">
  <name>Task 2: Create CONTRIBUTING.md</name>
  <files>CONTRIBUTING.md</files>
  <action>
Create CONTRIBUTING.md at repo root with the following structure:

1. **Title**: "# Contributing to AgenticCRM"

2. **Prerequisites**:
   - Rust 1.85 or later (`rustup update stable`)
   - Git
   - macOS recommended (keyring integration uses macOS Keychain; Linux needs libsecret)

3. **Getting Started**:
   ```bash
   git clone https://github.com/pmannion/agenticcrm.git
   cd agenticcrm
   cargo build
   cargo test
   ```

4. **Project Structure**: Brief overview of `src/` layout:
   - `src/main.rs` -- CLI entry point and command definitions (clap derive)
   - `src/commands/` -- CLI command handlers (thin wrappers around ops)
   - `src/ops/` -- Business logic layer (used by CLI, TUI, and MCP)
   - `src/mcp/` -- MCP server implementation (tools, resources, transport)
   - `src/tui/` -- Interactive terminal UI (ratatui)
   - `src/sync/` -- CardDAV sync engine
   - `src/models/` -- Contact data model, parsing, serialization
   - `contacts/` -- Contact markdown files (data directory)
   - `.schemas/` -- YAML schema definitions
   - `templates/` -- Contact templates

   Verify this structure by checking actual directories: `ls src/`. Adjust if any directories don't exist or are named differently.

5. **Development Workflow**:
   - Build: `cargo build`
   - Test: `cargo test`
   - Lint: `cargo clippy`
   - Format: `cargo fmt`
   - Release build: `cargo build --release`

6. **Code Conventions**:
   - All business logic in `src/ops/` -- CLI commands are thin wrappers
   - Functions return `Result<T>` with `OpsError` (thiserror-based)
   - Dates are always YYYY-MM-DD format
   - Tags are lowercase, hyphenated
   - Contact files named lowercase, hyphen-separated: `firstname-lastname.md`

7. **Testing**:
   - Unit tests in source files
   - Integration tests use `tempfile` crate for isolated test directories
   - Run specific test: `cargo test test_name`
   - Run with output: `cargo test -- --nocapture`

8. **Pull Requests**:
   - Keep PRs focused on a single concern
   - Ensure `cargo test` passes
   - Ensure `cargo clippy` has no warnings
   - Describe what and why in the PR description

Do NOT include: CoC reference, issue templates, security policy, CLA. Keep it practical and concise.
