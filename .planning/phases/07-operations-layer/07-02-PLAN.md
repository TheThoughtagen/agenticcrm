1. Create `src/ops/sync.rs` with:

   **Structs:**
   - `SyncCredentials { pub apple_id: String, pub app_password: String }`
   - `SyncOpts { pub force: bool, pub dry_run: bool }`
   - Move `SyncResult`, `SyncedContact` from commands/sync.rs (keep Serialize+Debug, Display stays in commands/)
   - Move `PushSyncResult`, `PushSyncDetail` from commands/sync.rs (same pattern)

   **Functions:**
   - `sync_pull(root: &Path, credentials: &SyncCredentials, filter: &SyncFilter, opts: &SyncOpts) -> Result<SyncResult, OpsError>`
     Extract the pull logic from `run_sync()` in commands/sync.rs. This includes: CardDavClient creation, address book discovery, PROPFIND listing, vCard fetching, contact creation/update, ETag caching, snapshot caching. Progress println!s stay in CLI wrapper (they are presentation).

   - `sync_push(root: &Path, credentials: &SyncCredentials, filter: &SyncFilter, opts: &SyncOpts) -> Result<PushSyncResult, OpsError>`
     Extract from `run_push()`. Includes: changeset computation, dry-run preview data, execute_push call, result building.

   - `sync_bidirectional(root: &Path, credentials: &SyncCredentials, pull_filter: &SyncFilter, push_filter: &SyncFilter, opts: &SyncOpts) -> Result<(SyncResult, PushSyncResult), OpsError>`
     Calls sync_pull then sync_push. Returns both results.

   **Error mapping:** CardDAV errors map to `OpsError::SyncError(e.to_string())`. File I/O errors map to `OpsError::Io`.

   **CRITICAL -- update_existing_contact fix (per CONTEXT.md):**
   The current `update_existing_contact` in commands/sync.rs writes directly with `format!("---\n{}---\n\n{}", fm, existing.body)` instead of using `store::serialize_contact_file()`. During extraction, route this through `store::serialize_contact_file()` to fix the tech debt. Verify output is identical for existing contacts.

   **Credentials handling:** Ops functions receive `SyncCredentials` -- they never load from keyring or config. The CLI handler loads credentials and constructs the struct.

   **Filter handling:** Ops receives `&SyncFilter` directly. CLI handler merges config + CLI flags and passes the result.

3. Refactor `src/commands/sync.rs`:
   - `run_setup()` stays unchanged (interactive credential prompting is CLI-only per CONTEXT.md)
   - `run_push()` becomes thin wrapper: load credentials from keyring, construct SyncCredentials/SyncOpts, call `ops::sync_push()`, format output
   - `run_sync()` becomes thin wrapper: load credentials, construct structs, call `ops::sync_pull()` or `ops::sync_bidirectional()`, format output
   - Keep `Display` impls for result types in commands/sync.rs
   - Keep `extract_uid_from_href` where it is (or move to ops/sync.rs since it's sync business logic)

4. Verify: `cargo build && cargo test` -- all pass, no behavior changes.
