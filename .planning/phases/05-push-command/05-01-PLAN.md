  <name>Task 1: Implement execute_push body and add PushResult Display/Serialize</name>
  <files>src/sync/push.rs</files>
  <action>
    Replace the stub `execute_push` function body in `src/sync/push.rs` with a full implementation. Also add `Display` and `Serialize` derives/impls to `PushResult` and `PushDetail` so they work with `format::output()`.

    **execute_push implementation (~80-100 lines):**

    1. Initialize a mutable `PushResult` with all zeros.

    2. **Process creates** (for cf in changeset.creates):
       - Serialize: `vcard_write::contact_to_vcard(&cf.contact)?`
       - Generate UUID: `uuid::Uuid::new_v4().to_string()`
       - Build URL: `CardDavClient::build_vcard_url(addressbook_url, &uuid)?`
       - PUT with no etag: `client.put_vcard(&url, &vcard_text, None)`
       - On success:
         - If returned etag is empty, do a `client.fetch_vcard_list(addressbook_url)` and find the ETag for this resource by matching the UUID in the href. Use that etag instead.
         - Update contact frontmatter: read `cf.raw_frontmatter`, use `frontmatter::update_field` to set `source` to `icloud`, `source_id` to `"uuid"` (quoted), `etag` to `"new_etag"` (quoted). Write back to `cf.path` using the format `---\n{fm}---\n\n{cf.body}`.
         - Cache the vCard: `vcard_write::write_cached_vcard(crm_root, &uuid, &vcard_text)?`
         - Increment `result.created`, add PushDetail with action "created"
       - On error: increment `result.failed`, add PushDetail with action "failed" and error message. Continue (don't abort entire push).

    3. **Process updates** (for (cf, cached_vcard) in changeset.updates):
       - Serialize: `vcard_write::merge_contact_to_vcard(&cf.contact, &cached_vcard)?`
       - Build URL: `CardDavClient::build_vcard_url(addressbook_url, &cf.contact.source_id)?`
       - PUT with etag: `client.put_vcard(&url, &vcard_text, Some(&cf.contact.etag))`
       - On success:
         - Handle empty etag same as creates (PROPFIND fallback)
         - Update frontmatter etag field only. Write back to cf.path.
         - Update cache: `vcard_write::write_cached_vcard(crm_root, &cf.contact.source_id, &vcard_text)?`
         - Increment `result.updated`, add PushDetail with action "updated"
       - On error (including 412 Conflict): increment `result.failed`, add PushDetail with error. Continue.

    4. **Process deletes** (for (source_id, etag, name) in changeset.deletes):
       - Build URL: `CardDavClient::build_vcard_url(addressbook_url, &source_id)?`
       - DELETE: `client.delete_vcard(&url, &etag)`
       - On success:
         - Remove cache: `vcard_write::delete_cached_vcard(crm_root, &source_id)?`
         - Increment `result.deleted`, add PushDetail with action "deleted"
       - On error: increment `result.failed`, add PushDetail with error. Continue.

    5. **Process conflicts** (for (cf, local_etag, server_etag) in changeset.conflicts):
       - If `force` is true:
         - Treat as update: serialize via merge (read cache for source_id), PUT with If-Match using SERVER etag (not local etag, since server has the newer version and force means override).
         - Actually: use `Some(&server_etag)` for If-Match since that's the current server version.
         - On success: update frontmatter etag, update cache. Increment `result.updated`.
       - If `force` is false:
         - Skip, increment `result.conflicted`, add PushDetail with action "conflict" and error message like "server ETag {server_etag} differs from local {local_etag}".

    **Derive/impl additions:**
    - Add `#[derive(Serialize)]` to `PushResult` and `PushDetail` (add `use serde::Serialize;` import)
    - Implement `fmt::Display` for `PushResult`:
      ```
      Push complete: X created, Y updated, Z deleted, W conflicts
      ```
      If `failed > 0`, append `, F failed`.
    - Add `use std::fmt;` import

    **Important pitfall avoidance:**
    - The changeset takes owned `ContactFile` values. When iterating `&changeset.creates`, read `cf.path` and `cf.raw_frontmatter` to do file I/O independently. Do not try to mutate the changeset.
    - When put_vcard returns empty string for etag, use the PROPFIND fallback: call `client.fetch_vcard_list(addressbook_url)` and find the entry whose href contains the UUID.
    - Use `frontmatter::update_field` for etag updates (not manual string replacement).
    - Ensure frontmatter etag values are quoted: `format!("\"{}\"", new_etag)`.

       - Fetch server state: `client.fetch_vcard_list(&addressbook_url)?`
       - Load local contacts: `store::find_crm_root()`, `store::load_all_contacts(&crm_root)?`
       - Compute changeset: `push::compute_push_changeset(&crm_root, contacts, &server_entries)?`

         - Convert PushResult into PushSyncResult (copy fields + set dry_run=false)
         - Output via `format::output(&result, fmt)?`
