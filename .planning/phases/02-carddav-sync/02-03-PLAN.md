  <action>
    1. Add `Sync` subcommand to Commands enum in src/main.rs:
       ```rust
       /// Sync contacts from iCloud
       Sync {
           #[command(subcommand)]
           action: Option<SyncAction>,
           /// Force re-download all contacts (ignore ETags)
           #[arg(long)]
           force: bool,
           /// Show what would change without writing
           #[arg(long)]
           dry_run: bool,
       },
       ```
       Add SyncAction enum:
       ```rust
       #[derive(Subcommand)]
       enum SyncAction {
           /// Set up iCloud credentials
           Setup,
       }
       ```
       Wire in match arm: if action is Some(SyncAction::Setup) call run_setup, otherwise call run_sync.

    2. Create src/commands/sync.rs with two public functions:

    **`pub fn run_setup(fmt: &OutputFormat) -> Result<()>`**
    - Prompt user for Apple ID (email) using dialoguer::Input
    - Prompt user for app-specific password using dialoguer::Password (masked input)
    - Call config::store_credentials(apple_id, app_password)
    - Print success message: "iCloud credentials stored in macOS Keychain"
    - Print hint: "You can now run `acrm sync` to pull contacts"

    **`pub fn run_sync(force: bool, dry_run: bool, fmt: &OutputFormat) -> Result<()>`**
    Core sync flow:
    a. Load credentials via config::load_credentials(). On error, print "Run `acrm sync setup` first" and bail.
    b. Create CardDavClient::new(apple_id, app_password)
    c. Discover address book: client.discover_address_book(). Print "Discovering address book..."
    d. Fetch vCard list: client.fetch_vcard_list(&addressbook_url). Print "Found N contacts on iCloud"
    e. Load existing local contacts: store::load_all_contacts(crm_root)
    f. For each VCardEntry in the list:
       Simplest correct approach:
       1. Fetch each vCard: client.fetch_vcard(&vcard_url)
       2. Parse with map_vcard_to_contact to get the Contact (which includes source_id from UID)
       3. Check find_existing_by_source_id with that source_id
       4. If found and !force: check should_update(existing, &entry.etag). If no update needed, skip.
       5. If found and needs update: update the existing contact's fields (write over the file).
       6. If not found: create new contact file.
    g. For new contacts:
       - Generate raw frontmatter via store::generate_raw_frontmatter
       - After generating from template, use frontmatter::update_field and frontmatter::update_array_field to set all mapped fields (email, phone, etag, source_id, tags, etc.).
       - Create ContactFile with body from mapped_contact.notes (prepend to Notes section if non-empty)
       - If dry_run: print "[DRY RUN] Would create: {name}" and skip writing
       - Otherwise: write via store::write_contact
    h. For updated contacts:
       - Update the existing contact's raw_frontmatter with changed fields using frontmatter::update_field
       - If dry_run: print "[DRY RUN] Would update: {name}" and skip
       - Otherwise: write file directly to existing path
    i. Print summary:
       - "Sync complete: {new} new, {updated} updated, {unchanged} unchanged"
       - If dry_run: prefix with "[DRY RUN] "
    j. Support JSON output format: serialize summary as { "new": N, "updated": N, "unchanged": N, "contacts": [...] }

    3. Add `pub mod sync;` to src/commands/mod.rs.

    4. Apply field updates (email, phone, etag, source_id, tags) in sync.rs after generating the base frontmatter from template, using frontmatter::update_field and frontmatter::update_array_field. Keep store.rs focused.

    IMPORTANT: Handle errors gracefully at each network step. If discovery fails, give a clear error. If a single vCard fetch fails, log a warning and continue with the rest (don't abort the entire sync).
