<task type="auto">
  <name>Task 2: Create CardDAV client module</name>
  <files>src/sync/carddav.rs, src/sync/mod.rs</files>
  <action>
    1. Create src/sync/carddav.rs with:

    **Types:**
    ```rust
    pub struct CardDavClient {
        client: reqwest::blocking::Client,
        apple_id: String,
        app_password: String,
        base_url: url::Url,
    }

    pub struct VCardEntry {
        pub href: String,       // URL path to the vCard resource
        pub etag: String,       // ETag for change detection
    }
    ```

    **Public API:**
    - `CardDavClient::new(apple_id: &str, app_password: &str) -> Result<Self>`
      Creates reqwest::blocking::Client with redirect policy (up to 5 redirects).
      Base URL: `https://contacts.icloud.com/`

    - `pub fn discover_address_book(&self) -> Result<url::Url>`
      Three-step PROPFIND chain:
      a. PROPFIND base_url with Depth:0, body requesting `current-user-principal` -> extract principal href
      b. PROPFIND principal URL with Depth:0, body requesting `addressbook-home-set` -> extract home href
      c. PROPFIND home URL with Depth:1, body requesting `resourcetype`, `displayname`, `getctag` -> find the collection with resourcetype=addressbook, return its URL

      Use url::Url for resolving relative URLs against the base. Each PROPFIND sends XML body with correct DAV: and CardDAV namespaces.

    - `pub fn fetch_vcard_list(&self, addressbook_url: &url::Url) -> Result<Vec<VCardEntry>>`
      PROPFIND on addressbook_url with Depth:1, requesting `getetag` + `resourcetype`.
      Parse response to extract each vCard resource href and etag.
      Filter to only include resources that are NOT collections (i.e., actual vCard entries).

    - `pub fn fetch_vcard(&self, vcard_url: &url::Url) -> Result<String>`
      Simple GET request to vcard_url. Returns the raw vCard text body.

    **Private helpers:**
    - `fn propfind(&self, url: &url::Url, depth: &str, body: &str) -> Result<String>`
      Sends PROPFIND request with basic auth, Content-Type: application/xml, Depth header, returns response body string.
      Checks for 207 Multi-Status response. Returns error on 401 ("Authentication failed -- ensure you're using an app-specific password from appleid.apple.com"), 403, or other error codes.

    - `fn parse_principal(xml: &str) -> Result<String>`
      Extracts href from `current-user-principal` response using quick-xml.

    - `fn parse_addressbook_home(xml: &str) -> Result<String>`
      Extracts href from `addressbook-home-set` response using quick-xml.

    - `fn parse_addressbook_collection(xml: &str) -> Result<String>`
      Finds the response entry with resourcetype=addressbook, returns its href.

    - `fn parse_vcard_entries(xml: &str) -> Result<Vec<VCardEntry>>`
      Parses multi-status response to extract VCardEntry list (href + etag for each non-collection resource).

    **XML Parsing approach:** Use quick-xml Reader to walk the XML tree manually (not serde derive -- WebDAV XML with namespaces is easier to handle with event-based parsing). Look for specific element local names: `href`, `current-user-principal`, `addressbook-home-set`, `getetag`, `resourcetype`, `addressbook`.

    2. Update src/sync/mod.rs to add `pub mod carddav;` export.

    **NOTE:** This module cannot be meaningfully unit-tested without a real CardDAV server. The XML parsing helpers CAN be tested with sample XML. Include `#[cfg(test)]` tests for:
    - parse_principal with sample iCloud-like XML response
    - parse_addressbook_home with sample XML response
    - parse_vcard_entries with sample multi-status XML

    Use realistic sample XML based on the WebDAV spec (see research doc for PROPFIND request/response patterns).
