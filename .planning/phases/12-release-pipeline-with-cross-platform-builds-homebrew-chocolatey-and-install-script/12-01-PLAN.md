2. Add a `[dist]` section at the end of Cargo.toml (cargo-dist configuration):
   ```toml
   [dist]
   cargo-dist-version = "0.31.0"
   ci = ["github"]
   installers = ["shell", "powershell", "homebrew"]
   targets = [
       "aarch64-apple-darwin",
       "x86_64-apple-darwin",
       "x86_64-unknown-linux-gnu",

   tap = "TheThoughtagen/homebrew-tap"
   publish-jobs = ["homebrew"]
   pr-run-mode = "plan"
   install-updater = true
   allow-dirty = ["ci"]
   ```

   The `allow-dirty = ["ci"]` is important: it lets cargo-dist regenerate the CI workflow even when the git tree is dirty (common during development).

<task type="auto">
  <name>Task 2: Generate release workflow and create release-plz config</name>
  <files>.github/workflows/release.yml, release-plz.toml, .github/workflows/release-plz.yml, cliff.toml, CHANGELOG.md</files>
  <action>
1. Install cargo-dist if not already installed:
   ```bash
   cargo install cargo-dist --locked 2>/dev/null || true
   ```

2. Create `.github/workflows/` directory:
   ```bash
   mkdir -p .github/workflows
   ```

3. Generate the release workflow by running:
   ```bash
   cargo dist generate-ci
   ```
   This reads the `[dist]` section from Cargo.toml and produces `.github/workflows/release.yml`. Do NOT hand-edit this file — it is generated and maintained by cargo-dist.

   If `cargo dist generate-ci` fails (e.g., cargo-dist version mismatch), fall back to creating the workflow manually based on the cargo-dist 0.31.0 template from the research doc. But try the generator first.

4. Create `release-plz.toml` in the project root:
   ```toml
   [workspace]
   changelog_update = true
   git_tag_enable = true
   git_release_enable = false
   publish = false
   semver_check = true
   ```

   Notes:
   - `git_release_enable = false` because cargo-dist handles GitHub Releases (not release-plz)
   - `publish = false` because we are NOT publishing to crates.io yet (can enable later)
   - `semver_check = true` uses cargo-semver-checks to validate version bumps

5. Create `.github/workflows/release-plz.yml`:
   ```yaml
   name: Release-plz

   on:
     push:
       branches: [main]

   permissions:
     pull-requests: write
     contents: write

   jobs:
     release-plz:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
           with:
             fetch-depth: 0
         - uses: dtolnay/rust-toolchain@stable
         - uses: release-plz/action@v0.5
           env:
             GITHUB_TOKEN: ${{ secrets.RELEASE_PLZ_TOKEN }}
   ```

   IMPORTANT: Uses `RELEASE_PLZ_TOKEN` (a Personal Access Token), NOT `GITHUB_TOKEN`. This is because tags created by GITHUB_TOKEN do not trigger downstream workflows (GitHub prevents infinite loops). The PAT must have `repo` scope to trigger the cargo-dist release workflow.

6. Create `cliff.toml` for git-cliff changelog configuration:
   ```toml
   [changelog]
   header = """
   # Changelog\n
   All notable changes to this project will be documented in this file.\n
   """
   body = """
   {% if version %}\
       ## [{{ version | trim_start_matches(pat="v") }}] - {{ timestamp | date(format="%Y-%m-%d") }}
   {% else %}\
       ## [unreleased]
   {% endif %}\
   {% for group, commits in commits | group_by(attribute="group") %}
       ### {{ group | striptags | trim | upper_first }}
       {% for commit in commits %}
           - {% if commit.scope %}*({{ commit.scope }})* {% endif %}\
               {% if commit.breaking %}[**breaking**] {% endif %}\
               {{ commit.message | upper_first }}\
       {% endfor %}
   {% endfor %}\n
   """
   trim = true

   [git]
   conventional_commits = true
   filter_unconventional = true
   split_commits = false
   commit_parsers = [
       { message = "^feat", group = "Features" },
       { message = "^fix", group = "Bug Fixes" },
       { message = "^doc", group = "Documentation" },
       { message = "^perf", group = "Performance" },
       { message = "^refactor", group = "Refactoring" },
       { message = "^style", group = "Styling" },
       { message = "^test", group = "Testing" },
       { message = "^chore\\(release\\)", skip = true },
       { message = "^chore", group = "Miscellaneous" },
   ]
   filter_commits = false
   tag_pattern = "v[0-9].*"
   ```
