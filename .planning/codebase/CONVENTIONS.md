# Coding Conventions

**Analysis Date:** 2026-03-05

## Languages

**Rust (primary):** All CLI logic in `src/`. Edition 2024.

**Bash (secondary):** Utility scripts in `scripts/`. Used for simple operations and imports.

**Markdown + YAML:** Data format for contacts in `contacts/`.

## Naming Patterns

**Files (Rust):**
- Use `snake_case.rs` for all source files
- One module per file: `src/commands/add.rs`, `src/commands/list.rs`
- Module index files: `mod.rs` in each directory

**Files (Bash):**
- Use `kebab-case.sh` for script files: `add-contact.sh`, `due-followups.sh`

**Files (Data):**
- Contact files: `firstname-lastname.md` (lowercase, hyphen-separated, alphanumeric only)
- Generated by `Contact::slug()` in `src/models/contact.rs`

**Functions:**
- Use `snake_case` for all Rust functions
- Command entry points are always named `run()` with relevant parameters
- Example: `pub fn run(name: &str) -> Result<()>` in `src/commands/add.rs`

**Variables:**
- Use `snake_case` for all Rust variables
- Abbreviation `cf` is the standard shorthand for `ContactFile`
- Abbreviation `c` is the standard shorthand for `Contact` (usually `&cf.contact`)

**Types:**
- Use `PascalCase` for structs and enums: `Contact`, `ContactFile`, `Relationship`, `Status`, `Priority`
- Enum variants are `PascalCase`: `LostTouch`, `Acquaintance`

**Constants:**
- Use `SCREAMING_SNAKE_CASE`: `FRONTMATTER_DELIMITER` in `src/store.rs`

## Import Organization

**Order (observed in all source files):**
1. Standard library imports (`std::path::Path`, `std::path::PathBuf`)
2. External crate imports (`anyhow::Result`, `chrono::Local`, `colored::Colorize`)
3. Internal crate imports (`crate::models::Contact`, `crate::store`)

**Grouping:**
- Each group separated by a blank line
- Multiple items from same crate on one `use` line with braces: `use anyhow::{Context, Result, bail};`

**Path Style:**
- Use `crate::` prefix for internal imports
- Example from `src/commands/add.rs`:
```rust
use anyhow::Result;
use uuid::Uuid;

use crate::models::{Contact, ContactFile, Priority, Relationship, Status};
use crate::store;
```

## Error Handling

**Framework:** `anyhow` crate for all error handling.

**Patterns:**
- All command `run()` functions return `anyhow::Result<()>`
- `main()` returns `anyhow::Result<()>` — errors propagate to user as messages
- Use `bail!()` for business logic errors (e.g., "No contact matching '{name}'")
- Use `.with_context(|| ...)` for adding context to IO/parse errors
- Use `.context("message")` for simple static context strings
- Use `?` operator for propagation throughout

**Error message style:**
- User-facing: include the user's input in the message: `bail!("No contact matching '{name}'")`
- IO errors: include file path: `format!("Failed to read {}", path.display())`
- Non-fatal warnings: `eprintln!("Warning: skipping {}: {e}", path.display())` in `src/store.rs:65`

**Example (from `src/commands/show.rs`):**
```rust
if matches.is_empty() {
    bail!("No contact matching '{name}'");
}
if matches.len() > 1 {
    let names: Vec<_> = matches.iter().map(|cf| cf.contact.name.as_str()).collect();
    bail!("Multiple matches for '{name}': {}", names.join(", "));
}
```

## Command Structure

**Every command follows this pattern (in `src/commands/*.rs`):**
1. Single public `run()` function as the entry point
2. Resolve CRM root via `store::find_crm_root()?`
3. Load contacts via `store::load_all_contacts(&root)?`
4. Filter/process contacts
5. Print output to stdout
6. Return `Ok(())`

**Contact lookup pattern (used in `show.rs`, `log.rs`):**
```rust
let name_lower = name.to_lowercase();
let matches: Vec<_> = contacts
    .into_iter()
    .filter(|cf| cf.contact.name.to_lowercase().contains(&name_lower))
    .collect();

if matches.is_empty() {
    bail!("No contact matching '{name}'");
}
if matches.len() > 1 {
    let names: Vec<_> = matches.iter().map(|cf| cf.contact.name.as_str()).collect();
    bail!("Multiple matches for '{name}': {}", names.join(", "));
}
```

## Output Formatting

**Terminal colors:** Use `colored` crate (v3).
- Names: `.bold()`
- Secondary info (company, tags, status): `.dimmed()`
- Overdue dates: `.red()`
- Import from `colored::Colorize`

**Output style:**
- Human-readable, one contact per line for list/search
- Summary count at the end: `println!("\n{} contacts", contacts.len())`
- Empty state messages: `"No contacts found."`, `"No follow-ups due. You're all caught up."`

## Serde Conventions

**Derive both `Serialize` and `Deserialize` on all model structs and enums.**

**Enum serialization:**
- `Relationship` and `Priority`: `#[serde(rename_all = "snake_case")]`
- `Status`: `#[serde(rename_all = "kebab-case")]` (e.g., `lost-touch`)

**Optional fields:** Use `#[serde(default)]` on all fields except `id` and `name`.

**Field types:**
- Scalar optional strings: `String` with `#[serde(default)]` (empty string = absent)
- List fields: `Vec<String>` with `#[serde(default)]`
- Optional dates: `Option<NaiveDate>` with `#[serde(default)]`
- Optional enums: `Option<Enum>` with `#[serde(default)]`

## Shell Script Conventions

**All scripts in `scripts/` follow these patterns:**
- Shebang: `#!/usr/bin/env bash`
- Header comment explaining purpose and usage
- `set -euo pipefail` on every script
- Resolve CRM root: `CRM_ROOT="$(cd "$(dirname "$0")/.." && pwd)"`
- Input validation with usage message and `exit 1`
- Slug generation: `tr '[:upper:]' '[:lower:]' | tr ' ' '-' | tr -cd '[:alnum:]-'`
- UUID generation: `uuidgen | tr '[:upper:]' '[:lower:]'`

## Comments

**When to comment:**
- Doc comments (`///`) on public functions in `src/store.rs`
- Inline section comments for grouping struct fields (e.g., `// Contact info`, `// Professional`)
- YAML comments in templates and schema for field grouping

**No JSDoc/TSDoc equivalent enforced; keep doc comments brief and descriptive.**

## Module Design

**Exports:**
- `src/models/mod.rs` re-exports all public types: `pub use contact::{Contact, ContactFile, Priority, Relationship, Status};`
- `src/commands/mod.rs` re-exports submodules: `pub mod add; pub mod due;` etc.
- `src/store.rs` exposes public functions directly (no barrel file)

**Visibility:**
- Public functions: `pub fn` for module API
- Private functions: `fn` for internal helpers (e.g., `parse_frontmatter` in `src/store.rs`)
- All struct fields are `pub`
